WiFi

This page keeps the two Wi-Fi radios in separate roles so field work cannot accidentally remove the management connection.

Management · wlan0

Use this session for the Pi’s normal network connection. It starts with FFLF-ZONE, but you can enter another SSID to save it as a management network. Saved management profiles reconnect automatically; the PiKit hotspot is the fallback when none is available.

Use Saved management profiles to switch to a previously saved wlan0 profile. Use Nearby management networks to select a detected network; enter its password on the connection form if it is protected.

Field · wlan1

Use this session only for equipment, boat, or industrial networks. Connections made here are saved on wlan1 but do not reconnect automatically after a reboot.

Choose a detected network from Nearby field networks, or enter its SSID manually. Select Disconnect field radio when finished.

Monitor mode

Enable monitor mode takes wlan1 out of NetworkManager so it can listen for authorized wireless analysis. It cannot scan or join Wi-Fi while in monitor mode. Select Return to managed mode before connecting or scanning again.

Network lists

Each nearby-networks list shows about five networks at a time. Scroll inside the list to see additional scan results. Scan results are refreshed when the WiFi tab is loaded.

RTL-SDR

The console shares one RTL-SDR USB dongle across five tools. Only one can run at a time — starting a tracker while another is active is refused until you stop it.

FM scan

Run FM scan sweeps 88–108 MHz and plots the spectrum, marking the strongest stations. Hover the chart for the exact frequency and signal level under the cursor.

Select Identify on a detected station to listen live for up to 15 seconds and decode its RDS name. This can fail on a weak signal or a station that doesn't broadcast RDS.

ADS-B

Start ADS-B tracking decodes 1090 MHz squitter messages from nearby aircraft and lists flight, altitude, speed, track, and position. The page refreshes every few seconds while tracking is on. Select Stop ADS-B tracking to free the dongle.

AIS

Start AIS tracking decodes marine AIS broadcasts (161.975/162.025 MHz) from nearby vessels and lists name, MMSI, speed, course, and position. A vessel's name only appears once its static data message is received, which can take longer than its position reports.

LoRa

Start LoRa detector continuously sweeps 915–928 MHz and lists energy bursts (time, frequency, width, signal above that pass's own noise floor). It's a presence finder, not a packet decoder — it won't show device IDs or payloads, only that something transmitted nearby.

This band can be noisy from the Pi's own USB3 bus. The detector requires several adjacent bins to rise together (matching real 125–500 kHz LoRa channel widths) and auto-mutes any frequency that re-triggers more often than a real device would transmit, but a persistently busy result usually means local interference, not traffic. Moving the dongle to a USB2 port/hub, using a shorter/shielded USB cable, or adding a ferrite choke typically clears it up.

One dongle, one tool

FM scan/Identify, ADS-B, AIS, and LoRa all need exclusive access to the single RTL-SDR dongle. If a tab shows the dongle is busy, stop the active tracker on its own tab first.

GNSS

Reads position/fix data from a GNSS receiver connected over USB-serial — built for the Unicore UM982 dual-antenna RTK module.

Starting

Select Detect port & baud to have the console probe every /dev/ttyUSB*//dev/ttyACM* device at common baud rates and read back whatever it finds sending real NMEA or Unicore data — it prefills the port/baud fields on a match, usually in a couple of seconds. You can still enter both manually instead; the UM982 defaults to 115200 baud. Either way, select Start GNSS tracking once the fields are set. If the port fails to open, check the USB cable and that nothing else on the Pi already has it open.

Fix quality

The console reports the receiver's own NMEA GGA fix quality field as-is: No fix, GPS (autonomous), DGPS, RTK float, or RTK fixed. RTK fixed/float requires the receiver to already be configured with a correction stream (its own base station or an NTRIP source) — this console only displays what the receiver reports, it does not supply corrections.

Azimuth (dual-antenna heading)

The UM982's headline feature: with both antennas connected (ANT1 = master, ANT2 = slave), it computes a heading — the clockwise angle from true north to the master→slave baseline — independent of motion, unlike GPS course-over-ground. This has no standard NMEA sentence on this receiver; it only ships as the Unicore UNIHEADINGA log, which the console also parses.

The receiver must be told to send it, once, over a serial terminal at its working baud rate (a USB cable and something like screen/minicom, not this console): send UNIHEADINGA 1 (1 Hz on the current port) then SAVECONFIG so it survives a power cycle. Without this, the Azimuth/Pitch/Baseline/Heading-quality rows stay blank even though position still works.

Heading quality mirrors position fix quality but for the baseline solution: RTK fixed (Unicore NARROW_INT) is the precise, intended state; RTK wide-lane fixed/float states are usable but coarser; No solution means the receiver hasn't resolved a baseline yet (needs both antennas connected, clear sky, and a moment to converge). Antenna placement matters: heading is only accurate along the physical ANT1→ANT2 line, so mount both antennas fixed relative to whatever you want the azimuth of (e.g. a vehicle or vessel's bow line), not arbitrarily.

Events & telemetry log

Events lists only meaningful changes since you started using the console: session started/stopped, first fix acquired, fix-quality changes (e.g. GPS → RTK fixed, or a dropped fix), first heading acquired, and heading-quality changes — not a line per second, just the moments that matter. Telemetry log is the full picture: one row roughly every second showing fix/position/azimuth/heading at that moment, so you can scroll back through what happened during a session instead of only seeing the latest reading. Both lists persist across Stop/Start — only the live snapshot above resets when you start again — and are capped (200 events, 500 telemetry rows) so they don't grow forever.

Stopping

Select Stop GNSS tracking to close the serial port. Starting again clears the previously displayed fix until a new NMEA sentence (or UNIHEADINGA log) arrives.
